# Agent Instructions

- Do not create `try/catch` blocks unless explicitly requested.
- When asked to create a skeleton, create only the minimal file/folder structure and placeholders. Do not add implementation code unless explicitly requested.
- Do not create or update README files unless explicitly requested.

## README Documentation

- README code samples should be based on the project source code, but simplified for documentation readability.
- Use relative paths for README links to files in the current example folder, for example `./src/index.html` or `./src/script.js`.
- Use absolute links for external resources, product pages, documentation, demos, and repository-wide related examples when needed.
- Prefer a concise `## Overview` instead of separate repetitive `Quick Summary`, `What This Example Includes`, and `Use Cases` sections.
- Add `## Live Demo` when a CodePen or hosted demo exists.
- Add `## Geoapify API Key` explaining where to get a key from `https://myprojects.geoapify.com/`.
- Add `## APIs and Libraries` with columns: `Name`, `Description`, `Documentation`, `Used In This Example`.
- Keep `## Useful Links` focused on broad links and avoid duplicating links already present in `## APIs and Libraries`.
- For README SEO, use natural high-intent phrases in the title and opening paragraph, prefer descriptive screenshot alt text, and avoid legacy `Keywords:` footer lines.

## README Code Samples

- Add 1-2 sentences before each code sample explaining what it does.
- Add a short structured explanation after each code sample explaining how it works.
- Avoid snippets that depend on hidden variables or missing surrounding context unless the text clearly explains where they are inserted.

## Screenshots

- Store screenshots in the example's `screenshots/` folder.
- Rename screenshot files to match the example slug, for example `<example-slug>-screenshot.png`.
- Add a `## Screenshot` section with descriptive alt text.
